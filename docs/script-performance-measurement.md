# Beadwork 脚本回归成本测量

日期：2026-09-16。

本记录对应 G20。测量使用同一工作区、Python 3.14.7 和临时 Git/worktree fixture；数值是墙钟时间，不作为跨机器基准。

| 场景 | 基线 | 结构收敛后 | 观察 |
| --- | ---: | ---: | --- |
| 完整脚本回归 | 282.767 秒，246 项 | 275.443 秒，253 项 | 用例增加 7 项，时间下降约 2.6%；单次差异不足以宣称稳定加速 |
| ticket 状态套件 | 108.516 秒，34 项 | 104.156 秒，35 项 | 新增自动来源组装场景后仍略低；主要成本仍是真实 Git/worktree 与子进程 |
| final handoff 套件 | 32.240 秒，22 项 | 34.056 秒，23 项 | 增加一个最终自动来源场景后小幅上升 |
| 证据/controller/verification 基础 | 35.234 秒，58 项 | 行为保持 | 严格 JSON、hash、发布和命令记录没有出现单独的明显热点 |

动态加载路径已从 controller、executor、run-verification、phase verifier 中移除，主要收益是依赖方向和可测试性。现有数据没有证明需要跨命令缓存 hash 或验收结果；这类缓存会扩大来源变化漏检风险，因此本轮不增加缓存。大日志回归继续保留超过 200 KB 的二进制输出和有界 tail，未通过删除真实边界来缩短测试。

维护入口会记录每项命令的墙钟时间。后续只有在同一 fixture 多次重复显示稳定收益时，才调整 fixture 构建或同一次调用内的重复读取；独立命令仍重新核对 Git、来源 hash 与现场。

preflight 的同名 `.timing.json` 记录采集、语义阶段墙钟（含等待）和组装自检耗时；墙钟差额不等于纯模型推理耗时。这些指标用于维护分析，不影响 READY 判定。
